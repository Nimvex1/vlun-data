# V3 integration notes (operator decisions, read before review)

## Deliberately NOT done in this pass

1. **README.md untouched.** It is generated by `scripts/generate_readme.py` and
   has unrelated in-flight modifications in this worktree. A V3 README section
   should be added to the `generate_readme.py` template (figures from
   `reports/v3/dataset_summary.json`) and regenerated in a separate commit once
   the in-flight README work lands. The V3 integration report is
   `reports/v3/quality_report.md`.
2. **`pyproject.toml` version untouched** (`2.1.0` while `DATASET_VERSION` is
   `2.2`; the v2 gate tolerates this today). V3 versioning lives in
   `derived_v3/manifest.json` (`dataset_version 3.0`, `schema_version 3.0`).
   Unifying versions is a maintainer decision, not taken here.
3. **`V3/clones/` working trees NOT committed** (~3.1 GB, PDF-heavy,
   must-not-redistribute). `.gitignore` covers `V3/clones/*` except the
   tracked `V3/clones/MANIFEST.md` (clone pins). Provenance survives as
   clone-HEAD + per-file sha256 inside `jsonl_v3/`/`derived_v3/`.
4. **No exploit executed.** All L1 claims are published-PoC claims, never
   executions. `reproducibility = 0` for every record by construction.
5. **No per-finding PDF parsing.** The 10 PDF-heavy audit archives contribute
   report-level pointers (`RESEARCH_ONLY`) with honest per-row fields parsed
   from their README tables (network/platform/tech/commit columns where the
   table carries them). Per-finding extraction is queued, not faked.

## Known thin spots (stated, not hidden)

- **Hard negatives: 16** (Sherlock symmetrical `invalid/` only). C4 JSON rows
  carry no judge labels and Sherlock optimism has no `invalid/` folder, so no
  rejection claim is made there; raw unjudged submissions are `RESEARCH_ONLY`.
  Ingesting C4/Sherlock judging labels (duplicate/invalid rationale +
  mitigation PR links) is the highest-value V3 follow-up.
- **Per-finding language/ecosystem: 1,044 unknown ecosystems / 1,072 unknown
  languages**, concentrated in the flat-PDF archives. Source-level
  language/ecosystem coverage (Clarity, Sway, Soroban-Rust, Cosmos/IBC, ZK
  circuits) is recorded in `jsonl_v3/sources.jsonl`; per-finding attribution
  needs the PDF-parsing pass.
- **Normalized vulnerability class: 7,505 unknown.** Only SmartBugs rows carry
  a mapped class (DASP -> VLUN). Class normalization for audit/contest rows
  needs the finding-text pass (queued).
- **Fix commits: 47 exact.** Pashov fix-review hashes exist for a minority of
  reports; C4 mitigation PRs and Sherlock fix links are not vendored in the
  clones and need the judging-label pass.
- **Cross-source corroboration within V3 is folder/contest-local only**
  (same-title same-contest, same-folder non-best, byte-identical PoC mirrors).
  Audit<->contest<->patch matches across sources (e.g. RISC Zero via Veridise
  + Hexens, Granite via 5 auditors) need the PDF-parsing + judging-label
  passes; the confirmation sets are named in `V3/02_source_dossiers.md`.

## Reproducing this layer on a fresh clone

1. Populate `V3/clones/` with one shallow clone per remote + pin in
   `V3/clones/MANIFEST.md` (18 rows).
2. `python scripts/build_v3.py` (fails fast with exit 2 if clones are absent).
3. `python scripts/validate_v3.py` (33 checks; must be 33/33).
4. `python scripts/validate.py` (v1/v2.2 gate; unaffected by V3 files).
